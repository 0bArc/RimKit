# Build and ship

## Ship a mod

```text
rimkit mod ship path\to\MyMod
```

Writes `About/About.xml` from `meta.lua` and copies the mod into your RimWorld `Mods` folder. The folder is `RIMWORLD_MODS` if set, otherwise the default Steam locations. Pass a Mods folder as a second argument to override.

RimWorld locks DLLs while it runs. Close the game before shipping RimKit itself.

## Build the kit from source

You need Visual Studio (C++ tools), CMake, the .NET SDK, RimWorld and the Harmony workshop mod.

```powershell
rimkit build
```

That runs the native build (`src\native\build_release.bat`), builds the host (`dotnet build src\host\RimLuaHost.csproj -c Release`), and regenerates `mod/Auth/allowlist.json` from the built DLL hashes. Outputs go to `mod/Assemblies`, `mod/Native`, and `bin\rimkit.exe`.

If RimWorld or Harmony are not in the default place:

```powershell
dotnet build .\src\host\RimLuaHost.csproj -c Release `
  /p:RimWorldDir="D:\SteamLibrary\steamapps\common\RimWorld" `
  /p:HarmonyPath="D:\SteamLibrary\steamapps\workshop\content\294100\2009463077\Current\Assemblies\0Harmony.dll"
```

Then ship the kit itself the same way:

```text
rimkit mod ship .
```

## Generated files

Do not edit these, regenerate them:

| File | Generated by | When |
|------|--------------|------|
| `mod/About/About.xml` | `rimkit mod sync` (repo root or `mod/`) | `mod/meta.lua` changes |
| `mod/Auth/allowlist.json` | `rimkit build` | native or host changes |
| `src/editor/aliases.json` | the native CMake step, from `src/api/aliases.json` | the alias table changes |
| `src/editor/stubs/rimkit_unc.lua` | `node src/editor/tools/gen-unc-stubs.js` | aliases or stubs change |
| `infrastructure/docs/api/reference.md` | `node infrastructure/tools/gen-api-reference.js` | stubs or aliases change |

## Editor extension

```powershell
cd src/editor
npm run package
```

Produces `rimkit-<version>.vsix`. The package step regenerates the stubs first.
